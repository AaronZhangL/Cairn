# Domain docs

Cairn has one product vocabulary across `packages/core`, `packages/ui`, and `apps/desktop`. Read the root `CONTEXT.md` when it exists, and relevant decisions in `docs/adr/` before changing a domain concept. `docs/ARCHITECTURE.md` records module boundaries and implementation decisions.

Create `CONTEXT.md` or an ADR only when a term or decision is resolved. `CONTEXT.md` is a glossary of product terms, not an implementation plan. Use its terms in issues, specifications, code, and reviews. Surface a conflict with an existing ADR before changing the affected design.
